Build a dual-service banking platform with a custom blockchain using two native coins, GYDS and GYD, plus a full Internet Funds system. GYDS is the main chain coin used for fees, gas, and staking. GYD is a native stablecoin implemented at the consensus level, with deterministic mint/burn rules enforced by the chain. Nodes must use local embedded databases only for blocks, state, and balances; never use PostgreSQL, Redis, or any shared DB for consensus. Nodes sync only via P2P blocks. PostgreSQL is used only for indexing blockchain data, app data, users, wallets, cards, requests, notifications, and audit logs, and must be replicated and highly available. APIs and websites read from PostgreSQL only and must remain online if nodes restart.

Users get a wallet and an Internet Funds account at signup. Internet Funds are off-chain GYD balances stored in PostgreSQL. Admins can credit or debit Internet Funds instantly and reversibly. Blockchain funds (GYD & GYDS) are on-chain, irreversible, and fees are paid in GYDS. Users explicitly choose which service to use for every transaction.

The system supports send, request, and receive functions, with QR code scanning for wallets, cards, and requests. Internet Funds use atomic DB transactions, row-level locking, and idempotency keys for double-spend protection. Blockchain funds use nonce tracking, pending transaction locks, and replay protection.

Physical cards are supported: they hold no funds or private keys, are PIN-protected, and require user approval via the app before funds move. Admins can manage nodes, credit Internet Funds, freeze accounts or cards, approve withdrawals, and view immutable audit logs. All user actions, card actions, and transactions are logged. Security includes 2FA, device fingerprinting, WAF, rate limiting, and DDoS protection. The blockchain consensus remains local and deterministic, while Internet Funds remain fully functional and independent.

This design ensures a real banking experience, secure dual native coins, and separation between off-chain and on-chain services. And this must be a mobile phone app and a website user must able to download it
